# 微信小程序用户端需求分析

## 一、项目概述

### 1.1 产品定位
"直播竞拍大师"微信小程序用户端，面向C端消费者，提供实时竞拍购物体验。用户可通过小程序浏览商品、参与直播竞拍、管理订单、使用AI智能出价辅助等功能。

### 1.2 目标用户
- 有直播购物习惯的消费者
- 对竞拍模式感兴趣的网购用户
- 追求高性价比商品的消费者
- 喜欢互动式购物体验的年轻用户群体

### 1.3 技术选型
| 类别 | 技术 |
|------|------|
| 框架 | 微信小程序原生开发 |
| 语言 | TypeScript |
| 样式 | Less |
| 组件框架 | glass-easel |
| 渲染引擎 | Skyline |
| 实时通信 | WebSocket (Socket.IO) |
| AI集成 | 智谱GLM (带降级机制) |

## 二、功能模块详细需求

### 2.1 用户认证模块

#### 2.1.1 登录功能
- **需求描述**：用户通过用户名+密码方式登录系统
- **功能要点**：
  - 用户名/密码输入框，支持表单校验（非空、格式校验）
  - 密码加密传输（crypto-js AES加密）
  - JWT Token存储（access_token + refresh_token）
  - Token自动刷新机制
  - 登录失败友好提示
  - 登录状态持久化（本地存储）
- **接口依赖**：`POST /api/auth/login`

#### 2.1.2 注册功能
- **需求描述**：新用户注册账号
- **功能要点**：
  - 用户名、密码、确认密码输入
  - 用户名唯一性校验
  - 密码强度校验
  - 注册成功自动跳转登录页
- **接口依赖**：`POST /api/auth/register`

#### 2.1.3 Token管理
- **需求描述**：自动管理用户登录态
- **功能要点**：
  - access_token过期自动使用refresh_token刷新
  - 双Token均过期跳转登录页
  - 请求拦截器自动附加Token
  - 401响应自动触发刷新流程

### 2.2 发现/首页模块

#### 2.2.1 商品浏览列表
- **需求描述**：用户浏览所有可竞拍商品
- **功能要点**：
  - 商品卡片展示：图片、名称、起拍价、当前价、竞拍状态、倒计时
  - 商品分类筛选
  - 竞拍状态筛选（即将开始/进行中/已结束）
  - 下拉刷新、上拉加载更多
  - 骨架屏加载占位
  - 商品搜索功能
- **接口依赖**：`GET /api/products`、`GET /api/categories`
- **组件依赖**：`product-card`、`skeleton`、`tag`、`countdown`

#### 2.2.2 商品详情页
- **需求描述**：查看商品完整信息
- **功能要点**：
  - 商品图片轮播
  - 商品名称、描述、规格参数展示
  - 起拍价/加价幅度/封顶价展示
  - 竞拍状态和倒计时
  - 竞拍记录列表
  - 当前排行榜
  - 收藏商家功能
  - 页面浏览记录上报
- **接口依赖**：`GET /api/products/:id`、`GET /api/auctions`、`GET /api/favorites`
- **组件依赖**：`price-display`、`countdown`、`auction-list-sheet`

### 2.3 直播竞拍模块（核心模块）

#### 2.3.1 直播间页面
- **需求描述**：用户进入直播间参与实时竞拍
- **功能要点**：
  - 实时竞拍状态展示（当前价、倒计时、竞拍者信息）
  - WebSocket实时推送（新出价、价格更新、延时通知、竞拍结束）
  - 出价面板（bid-panel）：输入出价金额、快捷加价按钮
  - 智能出价提示：AI分析当前竞拍态势，给出出价建议
  - 出价校验：最低加价、封顶价、竞拍状态校验
  - 弹幕组件（danmaku）：实时展示竞拍动态
  - 竞拍排行榜实时更新
  - 竞拍结果弹窗（result-modal）：获胜/未获胜提示
  - 被超越提醒（outbid notification）
  - 竞拍延时通知
  - 退出直播间确认
- **接口依赖**：WebSocket连接、`POST /api/bids`、`GET /api/auctions/:id`
- **组件依赖**：`bid-panel`、`bid-dialog`、`countdown`、`danmaku`、`result-modal`、`auction-detail-sheet`、`auction-list-sheet`、`bottom-sheet`、`price-display`
- **分包策略**：直播间页面作为独立分包（`pages/live`），从发现页预加载

#### 2.3.2 出价功能
- **需求描述**：用户在竞拍进行中提交出价
- **功能要点**：
  - 5层出价校验链：基础校验 → 状态校验 → 最低出价校验 → 封顶价校验 → 智能提示
  - 出价金额输入（手动输入 + 快捷按钮）
  - 出价确认对话框
  - 出价成功/失败反馈
  - 防重复提交
  - 网络异常处理（离线提示、重试机制）
- **接口依赖**：`POST /api/bids`
- **校验逻辑**：`bid-validator.ts`

#### 2.3.3 智能出价提示
- **需求描述**：AI辅助用户做出出价决策
- **功能要点**：
  - 基于当前竞拍数据分析出价建议
  - 出价策略推荐（保守/适中/积极/狙击）
  - 风险评估提示
  - 最佳出价时机建议
  - AI服务不可用时降级为基础提示
- **接口依赖**：`GET /api/ai/user/bid-suggestion`
- **降级机制**：`ai-degradation.ts`

### 2.6 AI智能辅助模块

#### 2.6.1 出价建议
- **需求描述**：AI分析竞拍数据，给出出价建议
- **功能要点**：
  - 综合分析竞拍数据（出价历史、竞争对手、价格趋势）
  - 给出建议出价金额
  - 出价策略推荐（保守/适中/积极/狙击）
  - 风险评估（低/中/高）
  - 最佳出价时机建议（立即出价/等待/狙击）
  - 竞争对手分析（人数、出价模式、行为预测）
  - 价格预测（最终价格、价格范围、趋势）
  - 置信度展示
- **接口依赖**：`GET /api/ai/user/bid-suggestion`

#### 2.6.2 竞拍趋势分析
- **需求描述**：展示竞拍价格走势和趋势分析
- **功能要点**：
  - 价格历史图表
  - 统计指标（总出价数、独立竞拍者、平均出价、最高/最低出价）
  - 趋势洞察（动量、竞争强度、价格波动、紧急程度）
  - 价格预测
  - 智能建议列表
- **接口依赖**：`GET /api/ai/user/trend-analysis`

#### 2.6.3 智能提醒
- **需求描述**：AI驱动的竞拍提醒
- **功能要点**：
  - 最佳出价时机提醒
  - 竞争对手变化提醒
  - 价格预测提醒
  - 风险提醒
- **接口依赖**：`GET /api/ai/user/smart-reminders`

#### 2.6.4 AI降级机制
- **需求描述**：AI服务不可用时的降级策略
- **功能要点**：
  - 8个AI功能模块可用性监控
  - 60秒间隔定期健康检查
  - AI不可用时自动降级为预设方案
  - 错误计数和恢复阈值机制
  - 状态监听器模式（UI可感知AI状态变化）
- **实现文件**：`ai-degradation.ts`

## 三、非功能需求

### 3.1 性能需求
| 指标 | 要求 |
|------|------|
| 首屏加载时间 | ≤ 2秒 |
| 出价响应时间 | ≤ 500ms（网络正常情况下） |
| WebSocket消息延迟 | ≤ 200ms |
| 列表滚动帧率 | ≥ 30fps |
| 小程序包体积 | 主包 ≤ 2MB，总包 ≤ 20MB |

### 3.2 可用性需求
- 网络断开时给出友好提示，支持自动重连
- WebSocket断连自动重连（指数退避策略）
- AI服务降级时提供基础功能，不影响核心竞拍流程
- 数据缓存策略：列表数据本地缓存，减少请求次数

### 3.3 安全需求
- 密码AES加密传输
- JWT Token安全存储
- 请求签名防篡改
- 敏感信息脱敏展示
- 防重复出价提交

### 3.4 兼容性需求
- 微信版本 ≥ 7.0.0
- iOS / Android 双平台兼容
- 适配不同屏幕尺寸（rpx响应式布局）

### 3.5 用户体验需求
- 骨架屏加载占位，避免白屏
- 操作反馈及时（Toast/Modal提示）
- 竞拍倒计时醒目展示
- 出价成功动画效果
- 弹幕互动增强参与感
- TabBar快捷导航（发现/订单/我的）

## 八、数据流向

### 8.1 竞拍出价数据流
```
用户点击出价 → bid-validator校验 → bid-panel确认 →
bid.service.submitBid() → request.post(/api/bids) →
后端处理（乐观锁+Redis） → WebSocket推送 →
所有直播间用户收到 new_bid 事件 → UI更新（价格/排行榜/倒计时）
```

### 8.2 AI出价建议数据流
```
用户打开出价面板 → bid-panel请求AI建议 →
ai.service.getBidSuggestion() → request.get(/api/ai/user/bid-suggestion) →
后端UserAIService分析（出价历史+竞争对手+价格预测） →
返回建议（策略/风险/时机/置信度） → UI展示建议卡片
→ AI不可用时 → ai-degradation降级 → 展示基础提示
```

### 8.3 实时通信数据流
```
用户进入直播间 → socket.joinAuction(auctionId) →
Socket.IO连接 → 加入竞拍房间 →
监听事件：new_bid / price_update / time_extended / auction_ended / auction_won / outbid →
event-bus分发 → 各组件响应更新
```
